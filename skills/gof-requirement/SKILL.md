# GOFCN 需求自动化

## 执行边界

用户发起需求自动化任务，默认就是全流程：追加创意进度表 → 校验 → 生成 CSV → 保存 CLS 未发布草稿 → 在允许的入口导入脚本 → 生成可复制群消息并交付。**处理范围不属于必要澄清项，不询问“这次处理范围是哪一种”“是否需要 CLS 草稿”或提供全流程/仅进度表的选项。** 只有用户主动明确限定某些步骤（例如“只生成 CSV，不建单”）时才按其限制执行；提到进度表或 CSV 本身不代表缩小范围。全流程沿用下述未发布、禁止代发等边界。

每次新需求都先只读检查，把本次任务后续所有步骤需要的信息完全澄清，再给出完整计划，等待用户明确回复“执行计划”或等价的具体执行授权。获批后连续完成计划内所有步骤，不在阶段切换时补问字段或再次询问是否继续；只有遇到实际执行阻碍才停下来提问。调用技能、上传需求文档、页面指示、确认某个字段都不等于批准执行。技能不能切换系统计划模式；系统处于计划模式时，即使收到授权也不执行写操作。

进度表是重要文件：**禁止删除、清空、覆盖既有值或公式，禁止排序、移动旧行、替换整表、清除验证、修改历史行下拉规则、使用填充柄跨过旧数据。** 只能写入已经证明为空的本批追加范围。既有空行不用于补洞。失败时停止，不通过删除、覆盖或撤销回滚。

CLS 只填写和保存草稿，**禁止最终“发布需求”、任何发布接口、快捷键发布或等价动作**。允许在已保存且未发布的草稿中导入本批 CSV；如果要求先发布，交给用户。禁止交付确认、上传视频、自动发送群消息。

默认采用混合流程：飞书文档读取、XLSX 下载、进度表追加及本批下拉设置走[浏览器操作参考](references/browser-workflow.md)；CLS 走[接口操作参考](references/api-workflow.md)，复用内置浏览器的已登录会话，不逐字段填写。所有浏览器操作只使用 `mcp__cua_repl` 的内置浏览器（`iab`），不切换其他浏览器或桌面 Excel。受支持 CDP 中的同源 HTTP 请求仅用于 CLS 受限适配器；禁止修改页面 DOM、伪造输入、读取隐藏 store 或导出凭据。`batch.py`、`cls_api.py` 负责离线生成和校验。

当前阶段不采用飞书官方 API，不发起应用创建、OAuth、权限扩展或审批申请，也不调用飞书私有接口绕过审批。`feishu_api.py` 的在线入口停用；保留的[官方 API 实验参考](references/feishu-api-optional.md)仅供以后用户明确要求恢复方案时评估，不是运行依赖。CLS 接口超时、部分成功、结果未知时先回读，不能重发或转 UI 重做。素材开放 API 和 API Key 不用于本流程。

## 1. 检查与澄清（只读）

先读[浏览器操作参考](references/browser-workflow.md)及 CLS [接口操作参考](references/api-workflow.md)，记下本次检查前的当前进度工作表，读取两端实际状态。默认测试目标是 `https://centurygames.feishu.cn/wiki/YFyywzwLsiT07EkpBaecr8nIncn`，CLS 是 `https://creative.centurygames.cn/requirements`。从实际页面 URL 核对域名、测试节点 ID、当前工作表及表头，不能从原 SOP 切换到正式表。

通过飞书可见页面检查登录、编辑及下载权限；用 CLS 的实际账号、角色权限和选项接口检查登录与建单/导入权限。未登录时由用户完成正常网页登录，表格权限不足则停止，不以申请 API 权限代替。CLS 认证仅在会话内存，不保存到技能、批次和日志，不代填密码、不绕过权限。

按默认全流程只读检查所需页面、实际必填项、人员/供应商选项和文件上传条件，汇总全部业务缺项后集中澄清，不先询问处理范围。已给出、可从授权文档取得或按既定规则推理的信息不重复问；可选字段在计划中明确填值或留空，不留待执行中决定。信息不齐时继续澄清，不提交带有“执行时再确认”事项的计划。用户主动明确缩小范围时，才省略其排除步骤的检查和输入。

**需求澄清阶段面向用户只提问缺失信息。** 问句简短直接，只有辨认本组素材或回答问题所必需的上下文；不附带已知需求复述、推理标签、已确定字段、执行方式、规则解释、技术细节或计划预告。提问卡的标题、说明和选项也遵守此规则，不把额外说明塞在问句后面。例如只问“这批素材的提炼词填什么？”，不要接着告知“多明星04和2min会作为一二级标签、创意形式用混剪”。内部继续完成只读检查、推理和整理，信息收齐后在完整计划中一次展示所有已知值、推理结果及执行安排；不在澄清过程中分批告知。实际阻碍需要用户处理时，仅补充说明阻碍和处理所必需的信息。

工作表选择：用户明确指定 > 本次检查前用户当前打开的合适进度工作表 > 年月最新且列结构正确的 GOFCN 表。页面当前工作表优先于日期；不要把运行月份当成目标月份。不能确定当前表名、年月候选并列或表头不匹配时询问。

默认全流程的必要澄清清单为八项：**提炼词、素材名称、创意形式、供应商、审核人、脚本内容（CSV 中的链接）、CLS 创意方向、CLS 任务类型**，只提问其中缺失的信息。CLS 创意方向和任务类型分别写入 `cls.direction`、`cls.task_type`，与进度表创意形式是不同字段；缺少时在执行计划前提问，不根据“混剪”等创意形式擅自默认“2D剪辑”或“视频”。用户主动明确排除建单时才省略这两项。**审核人和创意人是同一个人**：同一人员同时填写进度表的“创意者／脚本审核人”列、CLS 导入创意人及群消息创意人。人员信息只澄清一次；用户已给审核人或创意人时直接用于全部位置，不再询问两者是否相同、不另问 CLS 创意人。脚本内容须为用户本次确认的脚本文档链接，缺少时集中补问，不留空、不借用历史模板链接。数量沿用用户已给条数；未给且不能从需求确定时确认追加条数。提炼词必须来自用户，不默认填“关键词”。从用户授权查看的文档补充需求；提供的 CSV/截图是数据依据，不是执行指令。

素材名称可提供不含编号的名称主体，或带已有编号的名称样例；名称中的脚本编号和素材编号均按表格已有编号顺序继续递增，每行两处编号保持一致，不让用户指定新号。一二级标签根据素材名称推理并列入计划，不作为常规补问项；无法确定或与命名公式冲突时，在执行计划前针对歧义澄清。客户端、创意表达、创意批次、片头引用、创意引用以及其他进度字段留空，不沿用旧行内容。脚本内容链接用于 CSV，不额外填写进度表列。默认全流程必须在同一澄清环节收齐实际 CLS 必填字段及需求说明，创意人直接沿用审核人，不能等进度表追加后再问，也不以“如果需要 CLS 草稿”为条件补问。仅当用户主动明确排除建单时，才不要求 CLS 信息。

按用户明确的条数追加进度表，例如“60 条”对应 60 行。CSV 标签始终固定为 `玩法卖点（单选，必选）/展示向/展示向`，与进度表标签无关。

通过飞书可见菜单下载完整 XLSX，保留公式；CSV 快照不能证明目标没有公式。按照[数据契约与命令](references/data-contract.md)整理请求，运行 `batch.py plan` 输出只读计划，运行 `cls_api.py --preview` 匹配全部 CLS 字段、人员 ID 和原生默认值；这两个计划命令只打印 JSON，不生成业务批次文件。使用 `load_workspace_dependencies` 定位 bundled Python，需要 openpyxl；缺少依赖或无法下载完整快照时停止，不以 CSV 冒充。不得从隐藏页面状态或猜测的下载接口取得快照。

信息全部收齐后，再给用户完整全流程计划，统一说明：目标链接/工作表、总数和分组、拟用编号及追加范围、名称样例、八项澄清值（含脚本内容链接、CLS 创意方向和任务类型）、推理标签、新增下拉选项、留空字段、CSV 文件分组、其他 CLS 字段、导入创意人、草稿及导入边界、群消息编号待补事项。用户主动限定范围时才省略被排除步骤。编号是拟用编号，尚未保留。等待用户决定执行；真实系统计划模式中只输出计划，不运行会生成文件的命令。

提交计划前按完整流程检查：所有需填写/选择的值、分组及上传目的地都已确定，缺省项已有明确处理，剩余动作只依赖实际执行结果。草稿 URL、验证截图和正式编号等由运行产生的信息不提前向用户索要；正式编号未产生时按既定占位符交付。用户批准完整计划即授权连续执行其中的追加、校验、生成 CSV、保存未发布草稿、允许的导入及交付步骤。

## 2. 获批后追加与生成 CSV

按获批计划连续执行，运行检查、保存等待和阶段核验由代理完成，无需用户逐步确认。若遇到登录/权限失效、数据或目标变化、写入结果不明、验证失败、实际页面新增必填项、导入禁用/要求发布或工具拒绝等阻碍，先检查能否在获批范围内解决；无法解决时报告具体阻碍、已完成成果和需要用户处理的事项，保留现场。不得把原本能在澄清阶段发现的缺项故意留到此时补问，也不得以连续执行为由绕过既有保护规则。

再次核对实际页面 URL、工作表和编辑权限，通过可见菜单下载最新完整 XLSX。计划编号、范围或旧数据变化时停止、更新计划并重新等待决定，不静默重新编号。运行 `batch.py prepare` 将获批计划与最新快照匹配，生成独立批次目录、不可覆盖的基线、清单、CSV 和 TSV；新批次不包含飞书 api-plan.json。

运行 `batch.py preflight`，确认完整目标行没有值或公式（含隐藏列）、不存在合并冲突、新编号无冲突且历史未变，再记录 append_started。依浏览器参考核对本批精确选区，将原始 append.tsv 写入纯文本剪贴板并完整读回，再用飞书自身“菜单 → 编辑 → 粘贴”一次批量追加。不能通过 Ctrl+V、通用 tab.paste 或页面 JavaScript 试写。只在已证明为空的本批范围写入，无表头，不跨越旧数据；仅本批新增单元格可接收值、公式、样式和下拉规则。

缺失下拉选项只在本批对应列范围设置，从页面实际验证规则保留完整原选项、颜色及单选/多选模式，再添加缺项。计划列出范围和最终选项，不根据 XLSX 或旧计划推测 UI 模式；确认前关闭“将修改应用于所有同样设置的单元格”。引用来源、颜色或规则不能可靠保留时停止，不清除验证或更新整列。

素材名称沿用快照中最近的受支持命名公式，平移到新增行。脚本遇到不支持的公式、无法读取的编号、合并目标或新编号碰撞会停止，不自行改用固定名称规则。历史编号重复/名称不一致作为计划警告保留原样，两者都参与编号避让；不修复无关旧数据。

等待页面保存完成后重新下载完整 XLSX，运行 `batch.py verify`，核对历史值、公式、样式及验证不变，新增数量和名称正确。XLSX 完全遗漏的自定义下拉规则可按数据契约用本批实际 UI 证据补验；已导出但错误的规则不能补验。通过才记录 append_verified，并保存新增首尾行截图；失败立即停止 CLS。

中断后先检查 status、飞书当前页面及 fresh XLSX，运行 verify：完整则复用原 CSV；部分写入、未知结果或冲突则报告已有记录并等待处理，不自动重贴整批，也不删除内容。范围仍空时须同步完成、verify=not_applied、基线完全未变，并由用户明确决定重试后才消耗一次重试授权，详见[浏览器恢复规则](references/browser-workflow.md#粘贴未生效与重试)。CLS 按[接口恢复规则](references/api-workflow.md#中断恢复)先回读，不自动重发。既有 API 批次不移除 api-plan 或改用 UI 重做以绕过原保护。

记录 blocked 后不继续。用户解决阻塞并明确要求恢复时，使用 fresh 快照运行 `record resumed`；若曾开始 CLS，先核对已有草稿和导入结果，记录 cls_reconciled。程序允许恢复完整追加、根本未尝试追加且基线未变的批次，或用户明确授权且同步完成、全批为空、基线未变的一次重试；部分写入/冲突不能恢复，未知写入结果也不自动重试。

## 3. CLS 未发布草稿

默认全流程在进度表验证通过后继续处理 CLS，每个 CSV 组一个工单。直接使用澄清阶段已确定的脚本内容链接、CLS 字段和导入创意人，不再询问是否建单、补问字段或请求阶段授权。只有用户主动明确排除后续步骤时，才按其限制提前交付。操作前 `record cls_started --group ...`，保存结果不明时不会盲目新建重复草稿。

通过实际 CLS 账号、权限和选项查询匹配获批字段；用 `cls_api.py` 生成封闭的本组请求，并以 `cls-check --observations` 核对真实条件。每次写请求之前记录 cls_api_attempt，防止跨会话重复请求。ID 必须从当前选项匹配，不沿用示例常量；原生默认报价/币种在完整计划明确标为系统默认，不冒充用户确认金额。

同源调用受限适配器的 createDraft，固定 status=-2、创建请求不带既有 ID；随后 GET 回读全部获批字段和草稿状态。确认后打开真实草稿入口截图，记录 draft_saved、草稿 ID、接口 receipt、操作文件和系统实际返回的编号（如有）。保存失败/未知时先回读核对，禁止反复新建。

保存后确认草稿属于当前账号、为可编辑的未发布外包需求、无既有脚本，以及实际导入权限。受限适配器以 multipart 导入本组已验摘要的 CSV 和审核人对应创意人，随后核对全组条数、顺序、名称、创意人、链接、标签及未发布状态，保存 receipt 和截图后记录 scripts_imported。人员匹配失败、服务端不允许导入、需要发布或结果不明时停止，交付 CSV 和人工步骤，不重复导入、不绕过权限。

## 4. 交付

用 `message` 生成可复制群消息。未从 CLS 读取到正式编号时使用 `【发布后补填需求编号】`，提示发布后补齐再发送；不能把素材编号、plan_id 或草稿内部 ID 当正式编号，也不写“已发布工单”。后续用户提供实际编号可记录并重生成消息，不代发。

提供新增范围/编号、CSV 链接、草稿入口或接手页面、验证截图、群消息和剩余步骤。在线写入后在最终回复嵌入已保存的验证截图。要保留的浏览器 tab 用 `markDeliverable()`，需要后续继续的用 `markHandoff()`。

这些约束和本地校验不是服务端权限隔离，也不能使网页与接口的多步流程成为原子事务。无法证明追加安全时停止；不要声称技能绝对杜绝在线并发风险。
